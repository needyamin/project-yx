Project YX: Engineered for Weak CPUs & 4K Export

Project YX is an open-source, modern desktop non-linear video editor engineered specifically to provide fluid timeline editing on weak, modest CPUs while preserving lossless 4K 60fps and 9:16 vertical exports with zero bloat and 100% local-first privacy.

App ID: com.projectyx.editor
License: GPL-3.0-or-later
Frontend: React 19 · Vite 8 · TS
Backend: Tauri 2 · Rust 2021 Workspace

Modular Backend

The 5 Specialized Rust Crates

Every piece of core logic in Project YX is isolated into independent crates with zero circular dependencies.

yx-detect Hardware Probe
crates/yx-detect

Probes system CPU cores, available RAM, GPU vendor, and hardware encoder capabilities at boot to assign an optimal performance tier.

  • Automatic detection of NVENC, AMF, and QSV
  • Configures thread budget to avoid freezing low-end PCs
  • Calculates whether background proxies are mandatory
yx-timeline State Machine
crates/yx-timeline

Pure in-memory data model for tracks, video/audio clips, cuts, markers, zones, and unlimited undo/redo history with zero disk I/O.

  • Instant transactional cut, ripple, slip, and razor operations
  • Immutable undo/redo snapshots with minimal memory use
  • Strict timeline boundary and collision validation
yx-media FFmpeg Driver
crates/yx-media

Wraps FFmpeg and ffprobe CLI execution (bundled out-of-the-box in releases). Handles high-speed metadata extraction and background multi-threaded export rendering.

  • Probes resolution, codec, framerate, and audio layout
  • Realtime stderr progress parsing for accurate UI export bars
  • Presets for YouTube, TikTok (9:16), Instagram, and 4K
yx-compositor Preview Engine
crates/yx-compositor

Manages preview filter budgets, viewport aspect ratios (16:9 landscape vs 9:16 vertical), and bridges CSS preview filters to export parameters.

  • Enforces render budget so preview playback stays at target fps
  • WYSIWYG mapping between webview filters and FFmpeg eq filters
  • wgpu native hardware rendering path under development
yx-proxy Proxy Transcoder
crates/yx-proxy

Generates lightweight, intraframe-friendly proxy media in the background so weak dual-core and quad-core CPUs can scrub 4K footage fluidly.

  • Runs in background threads without stuttering the UI
  • Automatic fallback when timeline playback drops frames
  • Seamless hot-swap: edit on proxy, export from original 4K source
Rust Workspace Dependencies
Cargo.toml (Edition 2021)

High-performance foundational crates powering cross-platform concurrency, error resilience, and serialization.

  • `serde` & `serde_json` for ultra-fast IPC serialization
  • `parking_lot` for ultra-low latency reader-writer locks
  • `thiserror` & `anyhow` for robust error hierarchies
Execution Engine

How It Runs on CPU vs GPU

Project YX dynamically switches its execution strategy based on detected hardware capabilities.

Budget & Fallback Path

Weak CPU Execution Path

Optimized for dual-core and quad-core laptops without dedicated graphics. Keeps system responsive under load.

✓
Automatic 720p Intra-Frame Proxy Generation Transcodes heavy H.265/AV1 source media into smooth fast-seeking proxies in the background.
✓
Capped Background Thread Budget Restricts background FFmpeg encodes to (N-1) CPU cores so the OS and UI never stutter or freeze.
✓
SIMD Memory Copy & Drop-Frame Prevention Preview engine intelligently scales down viewport render quality during rapid scrubber scrubbing.
Accelerated Path

Hardware GPU Acceleration Path

Leverages dedicated graphics cards (NVIDIA, AMD, Intel) to provide instantaneous 4K playback and rapid hardware encoding.

★
Hardware NVENC, AMF & QuickSync Encoders Directs export tasks to dedicated silicon encoding engines for up to 8x faster render times.
★
WebView2 GPU Compositing Hardware-accelerated CSS preview effects (contrast, brightness, saturation, opacity) rendered on GPU.
★
Next Phase: Direct wgpu Shader Pipeline Upcoming roadmap integration for zero-copy GPU video frame surfaces and custom WGSL compute shaders.

Processing Flow

End-to-End Media Pipeline

From dragging footage into the Project Bin to the final 4K render, here is how Project YX handles every byte non-destructively.

STEP 01

Import & Probe

Drag-and-drop or file picker. ffprobe extracts stream count, fps, dimensions, color space, and duration in milliseconds.

STEP 02

Timeline Assembly

Clips placed onto non-destructive tracks. Razor, Ripple, Slip, and Spacer cuts update the in-memory graph instantaneously.

STEP 03

Background Proxies

On Tier 2 and Tier 3 systems, yx-proxy quietly builds lightweight edit copies without stalling the user interface.

STEP 04

Realtime Preview

Monitors render preview with aspect toggle (16:9 or 9:16 vertical for TikTok). Visual filters preview in real-time.

STEP 05

FFmpeg Export

Constructs FFmpeg filtergraph. Renders in background thread with live percentage & ETA progress bar. Source quality preserved.

Advantages & Current Limitations

An objective comparison of where Project YX excels and what remains on the active roadmap.

✓

Why Creators Choose Project YX

  • ✓
    Lightweight & Fast: Launches in under 1 second. Consumes ~30MB RAM compared to 500MB+ in Electron editors.
  • ✓
    Native Weak-CPU Optimization: Low-spec laptops stay responsive via background proxies and thread capping.
  • ✓
    First-Class 9:16 Vertical Video: Built-in 9:16 preview aspect toggle and TikTok/Instagram presets.
  • ✓
    Zero Downscaling on "Best" Preset: Uses source resolution, source fps, x264 CRF 15, and slow preset for max fidelity.
  • ✓
    100% Free & Open Source (GPL-3.0): No subscription paywalls, watermarks, forced accounts, or telemetry.
  • ✓
    Zero-Setup & 100% Offline: Bundled media engine (FFmpeg & ffprobe) inside the package. Works offline immediately with zero prerequisites.
!

Current Phase 1 Limitations

  • !
    CLI Subprocess Architecture: Phase 1 communicates with bundled FFmpeg via subprocess streaming rather than deeply linked C ABI libavformat.
  • !
    Advanced Motion Tracking Pending: Optical flow retiming, 3D camera tracking, and curve keyframing are planned for future versions.
  • !
    macOS Universal Builds in Progress: Windows (EXE, MSIX, Portable) and Linux (AppImage) are currently prioritized.
  • !
    Plugin System Early Stage: Third-party plugin SDK and OpenFX integrations are scheduled for Phase 2 milestones.

Repository Tree & Quickstart

Commands to clone, run local development with hot-reload, and build production packages.

bash — project-yx workspace
# 1. Clone the repository and install dependencies
git clone https://github.com/needyamin/project-yx.git
cd project-yx
npm install

# 2. Launch local dev server (React 19 + Tauri 2 with hot reload)
npm run dev

# 3. Compile full release with code signing
npm run dist:release

# Workspace Directory Structure:
project-yx/
├── apps/desktop/          # Tauri 2 frontend & Rust shell
│   ├── src/               # React 19 UI: layout, bin, monitors, timeline, effects
│   ├── src-tauri/         # Desktop main binary & tauri.conf.json
│   └── package.json
├── crates/                # High-performance Rust backend crates

│   ├── yx-timeline/       # Transactional timeline model (zero-I/O cuts & undo)
│   ├── yx-media/          # FFmpeg probe, pipe stream & progress parser
│   ├── yx-compositor/     # Render filter budget & aspect ratio policy
│   └── yx-proxy/          # Background proxy media transcoder
├── scripts/               # Distribution automation (Inno, MSIX, Portable, Docker)
├── docker/                # Linux AppImage container build recipes
├── Cargo.toml             # Root Rust workspace configuration
└── README.md              # Documentation & contribution guidelines
